# Working inside herdr

Read this on the first turn inside herdr, as the global instructions say. Herdr comes in two forms that share these rules but not their commands. In the herdr terminal app, `HERDR_ENV` is set, and the commands written below apply. In the Herdr desktop app, `HC_TERMINAL_ID` is set instead, and the last section swaps in its commands. The tab rename needs no skill. For any other command, load the `herdr` skill in the terminal app, or the `hc` and `herdr-app` skills in the desktop app.

## Names

- **Name the tab first.** On the first turn, when you are the only agent and the tab label is a number or a lowercase slug that no other live session set for you, run `herdr tab rename "$HERDR_TAB_ID" <slug>` before you read the repo or start the task. A number is herdr's default and a slug is a previous agent's, so replace both, even for a short question. When the first message is too thin to name, rename on the turn the task becomes clear, and rename again when the task changes enough that the label would mislead.
- A label with a capital letter is one I typed, so leave it. Rename what you own whenever a name clearly helps: your tab, the panes you split, the agents you start, and your own agent name while it has none. A name another session gave you, like the agent name and workspace or tab label `hq` sets for its workers, stays, and so does everything another session owns. The sidebar shows each Claude agent's name, so the name is how I find its pane. Name an agent you start for its role or task, like `reviewer` or `nav-flicker`.
- **Each name says only what the level above it doesn't.** Names are lowercase slugs of one to three words, at most 16 characters, which is my sidebar width. A worktree's workspace already carries the task, so a tab there is named for its role, like `build` or `review`, not the task again. Label each pane you split by what it runs and its port, like `dev :3001`, so other sessions can see which ports are taken, and keep a worktree's branch short, since the workspace shows it. Your ids are in `HERDR_TAB_ID`, `HERDR_PANE_ID`, and `HERDR_WORKSPACE_ID`, so no lookup is needed. The commands here are written for Bash; in PowerShell, write `$env:HERDR_TAB_ID` and the like, since `"$HERDR_TAB_ID"` there expands to nothing. Your own agent name is not; `herdr agent get "$HERDR_PANE_ID"` shows it.
- I prefer three panes per tab. The next one goes in a new tab named for what it holds.

## Panes, servers, and sessions

- **A pane is for what outlives the session or needs me.** A dev server, a watcher, something I asked to watch, or a command that waits for my input runs in a sibling pane, never as a background job of the harness. Tests, builds, checks, and other commands that finish on their own run through the harness's own tools as usual. Split the pane from the current one with `herdr pane split --current --direction right --no-focus` and start the process with `herdr pane run`. Before starting a server, list the panes and reuse one that already runs it for this checkout.
- Wait for a server's ready line with `herdr pane wait-output <pane> --match <text> --timeout <ms>`, always with the timeout, since herdr otherwise waits forever. When a request fails, read the pane with `herdr pane read`.
- When you created a herdr worktree from another pane, its servers and its next session go in the worktree's own workspace, starting with the first pane `herdr worktree create` returned.
- When the global fresh-session split says to stop, start the next session yourself with herdr's agent commands. Start it with `herdr agent start` in a split pane, on this same harness and the model this session runs on, at the effort and `--autocompact` window your task named if it named them; the command returns once the agent is ready. `herdr agent prompt --wait --timeout` hands it the plan file path and the slice to build. Name it after your own agent name with the next free number, like `nav-flicker-2` from `nav-flicker` and `nav-flicker-3` from `nav-flicker-2`, or after the task's slug when you have no name, and give that name in this session's report, which you then finish.
- A helper whose result comes back into this task, like a review, research, or a lookup, runs as a subagent, since a pane is a whole second session to start and clean up. Start a helper in a pane the same way only when it has to outlive this session, when I asked to watch it, or when it needs a harness or model your subagents can't run, and `herdr agent wait --until --timeout` watches for it to block or finish.
- **Notifications.** A notification the global rules call for is `herdr notification show` with what you need as the title (herdr cuts it at 80 characters), and the `request` sound for a stop or `done` for a finish. Herdr's own alerts skip the tab I have open, so don't count on them.
- **Worktrees.** Run `git -C <this checkout> fetch origin`, then create one with `herdr worktree create --cwd <this checkout> --branch <name> --base origin/<default branch> --no-focus`, which groups it in the sidebar and copies its env files. Without `--base`, herdr branches from whatever this checkout has out, and without `--cwd`, from the workspace I have open, which may be another repo. Herdr's bootstrap plugin already copies env files into a worktree under `~/.herdr/worktrees`, so look for them before copying again. A pnpm repo with `virtualStoreType: global`, or the older `enableGlobalVirtualStore: true`, in `pnpm-workspace.yaml` is already installed by the herdr plugin, since that setting makes a worktree install near-instant, so look for `node_modules` first.

## In the Herdr desktop app

The rules above hold, and these commands replace the herdr ones. The desktop app runs every terminal in herdr-core, driven with `hc`, and arranges them with `herdr-app`. `$HC_TERMINAL_ID` is your terminal's address, like `t1`. The `HERDR_*` ids are unset, and an address stays the same when its pane moves. `hc` waits take seconds, not milliseconds.

- **Tab name.** `hc get "$HC_TERMINAL_ID" --json` shows your tab's id in its `herdr.tab` label, and `herdr-app do tab.rename --id <tab> --name <slug>` names the tab. A tab nobody named shows its number.
- **Names on terminals.** The desktop app has no pane labels, so label the terminal instead: `hc label <t> tc.label="dev :3001"` for a pane you split, and `hc label "$HC_TERMINAL_ID" tc.agent=<name>` for your own agent name. Other sessions read them with `hc get <t> --json` or find one with `hc ls --label <key>=<value> --json`, since plain `hc ls` leaves labels out. The sidebar doesn't show them yet.
- **Your pane.** `pane.split` splits whichever pane I have focused unless you name one, so pass `--pane <your pane>` every time. `herdr-app ls` lists each terminal with its `pane`, so find yours by `$HC_TERMINAL_ID`. The new terminal starts in that pane's folder. When you have no pane, which is how `hq` starts its workers, you are someone's child shown only in the agents list. Then start a server or your next session with `hc run --bg` instead of a split: a server as your own child with `--outlive-parent` when it should stay up after you, and your next session with `--parent <your parent> --outlive-parent --no-notify`, taking your parent from `hc get "$HC_TERMINAL_ID" --json`, so it nests where you did. I open either one by clicking it in the agents list.
- **Servers.** `herdr-app do pane.split --direction right --pane <your pane> --argv '["pnpm","dev","--port","3001"]'` opens the pane beside yours and prints its `terminal`. Before starting one, check `hc ls`, whose `agent` and `cwd` show what each terminal runs and where, and reuse one already running it in this checkout. `hc wait <t> --output <text> --timeout <s>` waits for the ready line, but it only matches output printed after the wait starts, so start it right after the split. When it times out, `hc read <t> --lines 100` shows whether the line went by. Read a failing server the same way.
- **Handoff and pane helpers.** Start the next session with `herdr-app do pane.split --direction right --pane <your pane> --argv '["claude","--name","<name>","--model","<model>","--effort","<level>","--autocompact","<window>","<first prompt>"]'`, leaving out `--effort` or `--autocompact` when your task didn't name it. The last argument is the plan file path and the slice to build, so there is nothing left to type into it. Then label it with `tc.agent=<name>`. `hc wait <t> --timeout <s>` returns when it stops working, and `reason: timeout` means it is still busy. A terminal started with plain `hc run` gets no pane and ends when you exit, so use the split for anything I should see.
- **Notifications.** The desktop app has no notification command. It alerts on its own when an agent blocks or finishes, so ending your turn is the notification.
- **Worktrees.** The desktop app has no worktree command. Run `git -C <this checkout> fetch origin`, then `git -C <this checkout> worktree add ~/.herdr/worktrees/<repo>/<slug> -b <branch> origin/<default branch>`, where the slug is the branch with each slash turned into a dash, the way herdr names its own worktree folders, so it starts from the default branch rather than whatever this checkout has out. Then open its space with `hc run --bg --outlive-parent --no-notify --cwd <that path> --label herdr.space=sp-<slug>-<unix time> --label herdr.tab=tb-<slug>-<unix time>`, adding a program after the flags or leaving it off for a shell. A space id the app hasn't seen becomes a new space named after the folder, without taking my focus the way `space.new` does. The bootstrap plugin doesn't run here, so copy the env files yourself and install on first need.
- **Closing.** `hc kill <t>` ends a terminal you started and closes its pane. Never stop or restart the core, since every terminal I have runs in it.
